# prData: Synthetic Long-Context Recall / Update

Each example is a long **context** of project status facts mixed with filler sentences. The query asks about the status of one project.

* **Recall:** the queried project is stated once.  
* **Update:** the queried project's status changes 1, 2, 4 or 8 times. The answer is the latest value.

All data is synthetic and was generated by our own code (`generate_data.py`, seed 5300).

## Split sizes

| Split | Examples | Recall | Update |
| :---- | ----: | ----: | ----: |
| train | 80,000 | 40,057 | 39,943 |
| dev | 10,000 | 4,968 | 5,032 |
| test | 10,000 | 5,075 | 4,925 |

The test set is reserved for final evaluation.

## Example

> Thanks everyone. Project Trout status: oasis. **Project Opossum is onion.** That is all. In other news, the design meeting is fully booked before noon. **Project Opossum is merged.** Also, the front desk has a new manager on Monday. Project Sycamore xstatus: guava. … Project Sycamore is velvet. Project Shark status: jasmine. …

> **Query:** What is the current status of Project Opossum? **Answer:** merged

Here `onion` is a stale (outdated) value. `oasis`, `guava`, `velvet` and `jasmine` are distractors, i.e. values of other projects.

## File format

Each split is a JSON Lines file (one JSON object per line):

```json
{"id": "train-000013", "task": "update", "context": "Thanks everyone. Project Trout status: oasis. ...",
 "query": "What is the current status of Project Opossum?", "answer": "merged", "target_entity": "Opossum",
 "stale_values": ["onion"], "distractor_values": ["oasis", "guava", "velvet", "jasmine"],
 "context_length": 128, "context_tokens": 128, "num_entities": 4, "num_updates": 1,
 "num_distractor_updates": 1, "num_facts": 6, "needle_position": 0.2422, "needle_position_bin": 1}
```

&nbsp;

| Field | Meaning |
| :---- | :---- |
| `task` | `recall` or `update` |
| `stale_values` | Earlier values of the queried project (empty for recall) |
| `distractor_values` | Values of all other projects |
| `context_length` | Length bucket: 128, 256, 512, 1024 or 2048 tokens |
| `context_tokens` | Exact token count of the context |
| `num_entities` | Number of projects in the context (2–64) |
| `num_updates` | Times the queried project changes (0 for recall) |
| `needle_position` | Where the answer sentence starts (0 \= start, 1 \= end); `needle_position_bin` puts it in one of five 20% bins |

## How the data was created

1. **Random names and values.** Names come from a pool of 260 and values from a pool of 265 names and values. They are re-paired in every example, so nothing can be memorized. No value repeats within an example. As a result, every wrong answer is either stale, a distractor for another project, or not in the context.  
2. **No shortcuts.** In the update task, other projects get updated too. One "decoy" project is always mentioned as often as the target. There are no clues in the context that reveal which project is asked about like the number of mentions or the position of the answer.  
3. **Filler.** Filler sentences such as "The team lunch ran late on Friday." pad the context to its exact length. Filler never uses project names or values.

We validated `validate_data.py` re-reads every context with an independent parser. That ensure the answer is the final stated value, stale and distractor values never match the answer, there are no duplicates, and all metadata is correct.

## Reproducing

```sh
python3 generate_data.py --out data  
python3 validate_data.py data
python3 make_archive.py data
```
